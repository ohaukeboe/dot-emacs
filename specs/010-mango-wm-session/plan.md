# Implementation Plan: Mango Window Manager Session

**Branch**: `010-mango-wm-session` | **Date**: 2026-11-11 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/010-mango-wm-session/spec.md`

## Summary

Add a toggleable `modules.mango` NixOS module that turns on nixpkgs
`programs.mango`, its own login screen (greetd + ReGreet), and a complete
session built from nixpkgs tools (waybar, fuzzel, mako, swaylock, swayidle,
hyprpolkitagent, cliphist, grim/slurp, brightnessctl, swaybg, nm-applet).
Mango's `config.conf` is generated by Home Manager and checked at build time
with `mango -p`. Session services bind to `mango-session.target` so they never
start under COSMIC. The COSMIC module gains `greeter.enable` so `laptop` can
run Mango's login screen while keeping COSMIC as a selectable session.

Research details: [research.md](research.md).

## Technical Context

**Language/Version**: Nix (flakes, nixpkgs pinned in `flake.lock`), NixOS
modules, Home Manager as a NixOS module.

**Primary Dependencies** (nixpkgs only): `mango` 0.18.4, `regreet` 0.5.0 +
greetd + cage, waybar, fuzzel, mako, swaylock, swayidle, hyprpolkitagent,
cliphist, wl-clipboard, grim, slurp, brightnessctl, swaybg, networkmanagerapplet,
foot, xdg-desktop-portal-wlr/-gtk, gnome-keyring.

**Storage**: N/A (generated config files; ReGreet's own state in `/var/lib/regreet`).

**Testing**: Nix evaluation and build (`nix flake check`, toplevel build of
`laptop`), assertion probes, a build-time `mango -c … -p` config check, and the
manual checklist in [quickstart.md](quickstart.md).

**Target Platform**: NixOS x86_64, machine `laptop` (AMD, `amdgpu`).

**Project Type**: NixOS configuration module.

**Performance Goals**: login to usable terminal in under 10 s (SC-001).

**Constraints**: nixpkgs-only packages (FR-009); zero change to the other three
machines (SC-005); COSMIC session unchanged except its greeter (FR-011).

**Scale/Scope**: one new module (~250 lines), one option added to
`modules/cosmic-de`, one machine entry.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

All five principles pass:

- **I. Evaluation-time checks**: typed options; greeter-clash and timeout
  assertions; `mango -p` turns config typos into build errors; binds use
  `lib.getExe`.
- **II. Determinism**: nixpkgs only, pinned by `flake.lock`; config
  generated, no manual post-install step (FR-013).
- **III. Fast gate**: no new `checks.*`; the `mango -p` check is part of the
  laptop toplevel build, not `nix flake check`.
- **IV. Single source of truth**: username from `config.user.username`; no ADR
  contradicted; keyboard/touchpad values mirrored from COSMIC (see below).
- **V. Toggleable modules**: `modules/mango/default.nix`, `mkEnableOption`,
  all under `mkIf`; reads only nixpkgs options, not COSMIC internals; the new
  `cosmic-de.greeter.enable` defaults to today's behaviour.

Post-design re-check: still Pass. One note on IV: keyboard layout and touchpad
settings now exist in both `modules/cosmic-de` and `modules/mango`. They use
different formats (COSMIC RON vs mango `k=v`), so sharing one Nix value would
add a translation layer for two short settings. Accepted; COSMIC is expected to
be removed (spec Clarifications), which ends the duplication.

## Implementation notes for tasks

1. `modules/cosmic-de`: `greeter.enable` (default `true`) wraps
   `services.displayManager.cosmic-greeter.enable`. The nixpkgs COSMIC
   desktop module does not enable the greeter itself (checked), so a plain
   `= cfg.greeter.enable` is enough.
2. `modules/mango`: `programs.mango.enable`; `systemd.packages = [ mango ]`
   (R1); `services.displayManager.regreet.enable = cfg.greeter.enable` with
   dark theme; `security.pam.services.greetd.enableGnomeKeyring`;
   gnome-keyring on, gcr-ssh-agent off; power-profiles-daemon on.
3. HM side under `home-manager.users.${config.user.username}`: each component
   bound to `mango-session.target`; `xdg.configFile."mango/config.conf".source`
   = validated derivation.
4. Config content: keyboard/touchpad from R3, `env=QT_QPA_PLATFORMTHEME,gtk3`,
   `exec_once` only for swaybg, bindings from the contract.
5. `laptop` composition per contract; verify other machines' `drvPath`s are
   unchanged.
